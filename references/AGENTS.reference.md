# Agent 实验行为规范

本仓库是「当代人工智能实验课 · 实验一（文本分类）」的实验现场。目标是结论有证据、过程可复现、提交者能解释每一步。

- 任务事实、阶段协议与实验矩阵见 [`WORKFLOW.md`](WORKFLOW.md)；要求的来源与时效（含教师对 PDF 的后续更新）见其第 1 节。
- 用户当前明确指示优先于本文件。
- 本文件约束 agent 的行为；机械校验由 `data-Project1/check_rigor.py` 执行。

## 1. 开始工作

- **每次实验前、以及每次开始实际工作前，先完整读一遍 `AGENTS.md` 与 `WORKFLOW.md`**（用户明确要求）。读本文件是第一步，不得跳过，也不得凭记忆替用旧版本。
- 读完后确认：当前处于阶段 0–8 的哪一步、上一阶段的完成判据是否满足、本次要跑哪些实验。
- 明确本次目标、拟改动的文件、验证方式；不顺手修改本次范围外的文件。
- 遇到要求冲突（`AGENTS.md` / `WORKFLOW.md` / PDF / 教师后续更新），比较来源与时效后取**最新且来源更高**者，并在文档中注明原要求、新要求与来源；不要默默取用其中一个，也不要默认 PDF 一定最新（本实验已出现报告页数被教师更新覆盖的先例）。

## 2. 证据规则

- 不编造任何结果、指标、引用或「已通过」的记录。
- 每个重要论断都必须能指向具体证据：日志、图表、脚本输出或命令。
- 区分 **实测 / 推断 / 不确定**，并在结论中标注。启发式推断（如类别名）不得表述为官方事实。
- 不把「代码跑通了」当作「结论成立」；不把中间产物当最终结果。
- 引用外部资料注明来源与版本；要求发生更新时，同时记录原要求、新要求与来源。转述（如「教师口头更新」）不得写成已核验事实，须标注证据等级。

## 3. 数据与实验纪律

- 先划分，再预处理。任何统计量（均值、方差、词表、IDF）**只能在训练集上拟合**。
- 验证集与测试集只 `transform`，不 `fit`、不 `fit_transform`。
- 测试集封存到阶段 6，不参与调参、选模型或任何决策。
- 一次只改一个因素，其余条件保持一致；对照组必须可比。
- 指标与比较方式在实验前确定，**不因结果好坏而更改**。
- 先跑通基线，再判断改进是否真实存在。
- 需要判断模型是否收敛、是否过拟合时，必须同时看训练集与验证集表现，不得只看单一数字。

## 4. 环境纪律

- 只用 conda，不用 pip。`data-Project1/environment.yml` 是环境的权威定义。
- 不得移除三条 BLAS pin（`libblas` / `libcblas` / `liblapack` 的 `=*=*openblas`）。换成 MKL 会导致首次 BLAS 调用原生崩溃。
- 不得用 `pip freeze` 生成依赖清单：本环境会输出本地构建路径，他人无法安装。
- 需要新依赖时，记录版本约束并同步更新 `environment.yml`，说明用途。

## 5. 记录与产物

- 每次实验记录：数据来源、处理方式、环境、运行命令、关键参数、随机种子、指标数值。
- 结果落盘到 `results/`，不只留在终端输出里。
- 训练中间产物（模型、词表、特征矩阵）**不得**作为可复用资产提交；诊断用拟合对象用完即弃。
- 保持相对路径，禁止绝对路径（PDF 明确反对）。
- 所有随机性通过 `config.py` 的 `SEED` 控制，不在脚本内散落魔数。
- 不在提交物中放置密钥、私人材料、虚拟环境、缓存或大体积数据。

## 6. 监控与自检

- 每个阶段结束时运行 `python check_rigor.py`（在 `data-Project1/` 内）。
- **存在 ERROR 时不得进入下一阶段**：先修复，或如实说明并取得用户确认。
- WARN 必须逐条给出正当理由；无法解释的 WARN 视为未通过。
- 自检脚本覆盖不到的方面（如分析方法是否恰当、结论是否过度外推），由 agent 自行申报，不得默认通过。
- 不得为了让自检通过而弱化检查项、改写断言或删除产物；修改 `check_rigor.py` 的判定逻辑需明确说明理由。

## 7. 交付与沟通

- 交付时说明：改了哪些文件、验证了什么、结果如何、还有什么未验证。
- 缺数据、缺依赖、缺算力时，如实记录未验证项及其影响，**不拿无关检查冒充验证**。
- 结果不理想时照实报告，不美化、不挑选有利数字而不作说明。
- 面向用户的汇报用简体中文；不使用 emoji。

## 8. 禁止事项

- 伪造或「预估」任何指标数值。
- 用测试集调参、选模型或做任何决策。
- 在划分前对全体数据做去重、统计、归一化或增强。
- 声称跑过某实验但实际未运行。
- 在 `predictions.csv` 未通过三项 assert 的情况下声称可提交。
- 修改 `draft_main.py`。
