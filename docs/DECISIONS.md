# 待采纳的业务语义与设计决策

本文件列出 Word 未明确的语义及项目解释。2026-10-15 S1 审阅后，D01–D10 均为 **accepted**，采纳者为本次获授权的 Codex agent；这是项目决定，不是教师另行确认，也不等于实现已通过测试。原 proposed 内容保留如下作为方案依据。

采纳记录必须包含：日期、执行者、来源/需求 ID、备选解释、所采纳方案、理由、影响、验收用例。若后续改变，追加新记录并标记替代关系，不抹去旧决定。

## D01 登录与匿名

关联 R02/R03/R10。原文同时要求填写者先登录及支持匿名。建议所有填写先登录；匿名表示创建者的统计、答案明细和导出不披露身份。服务端可保留仅用于判重与审计的私有标识，公开响应不能暴露。此方案不等于游客填写或不可追溯匿名。非匿名问卷在填写前明确说明身份披露范围。验收：TC-A02、TC-R04、TC-S03。

## D02 重复填写与幂等

关联 R10。建议新增 `allow_repeat`，默认 false，发布后本阶段冻结；false 按账号+问卷判重，true 时主动再次填写产生新答卷。网络重试使用同一个提交请求 ID，只产生一条答卷；新一轮填写使用新 ID。同一 ID 不同内容拒绝，不静默覆盖。匿名模式仍通过私有认证标识判重。发布版本变化后判重是按问卷还是按版本必须与新版本策略同步，本阶段建议按问卷。验收：TC-R03、TC-R04、TC-R05。

## D03 保存范围

关联 R09。建议第一阶段把“每次填写保存”定义为每次**成功提交**都持久化，失败输入不生成成功答卷；自动保存未完成草稿不在本阶段范围。页面须说明提交前未保存。若教师将“每次填写”解释为含未完成草稿，更新需求并增加草稿状态、隔离与恢复测试，不能宣称当前解释已获教师确认。验收：TC-R01、TC-R02、TC-E01。

## D04 跳转规则的确定性

关联 R08。建议规则结构为来源题 ID、类型化条件、目标题 ID、显式优先级。单选支持选项相等；多选支持 ANY/ALL 并明确空集合不命中；数字支持 eq/lt/lte/gt/gte。按优先级升序，首条命中生效；同优先级配置拒绝；无命中走下一顺序题，末题后结束。普通跳转仅向后，拒绝坏目标、自环和回跳；本阶段不引入提前结束指令。该限制符合原文向前示例，但属于可修订的项目范围。验收：TC-J01–TC-J05。

## D05 路径与必答

关联 R04/R08/R09。建议只校验实际可达路径上的必答题；被跳过题无需回答。改动早期答案后，客户端清除脱离新路径的答案，服务端从首题重算。客户端提交路径外答案、未知题号、旧版本题号或不完整必答路径时拒绝并提示修正，不能信任客户端自己报出的路径。验收：TC-J05、TC-R02。

## D06 校验边界

关联 R04–R07。建议数值上下界均包含；整数数学值判断，拒绝布尔值、NaN、Infinity 和隐式把任意字符串当数字。文本按 Unicode 码点计数、保留原文；是否 trim 用作“空答”判断须显式统一，建议全空白视为空答、长度按原始字符串计数。可选题空答时不触发非空约束；一旦非空则执行配置约束。多选不允许重复选项 ID 或非法 ID；min/max/exact 冲突、负数或超过选项数的配置拒绝发布。手机号按数字录入会丢失前导零，必须在文档说明示例局限，不把该风险隐藏在自动转换中。验收：TC-V01–TC-V05。

## D07 生命周期、时间与关闭竞争

关联 R03/R09/R10。建议 `draft → published → closed`，本阶段关闭后不重开。题目/选项/跳转及匿名/重复策略发布后不可变；截止时间可由创建者设置或调整并记录。仅 published 且服务端受理时刻严格早于截止时间可提交；UTC 存储，界面明确 Asia/Shanghai。正好到期、关闭后即使页面已打开也拒绝新提交。S2 必须明确“受理”的线性化位置及与关闭并发的先后规则，不能只写读取状态再插入。验收：TC-Q03、TC-R05。

## D08 统计口径

关联 R11。建议以成功答卷为基本计数单位；显示成功提交次数及去重填写人数，清楚区分。单选每选项次数及该题非空有效回答数；若允许重复，再提供每选项去重人数和该题去重人数以保留原文“人数”含义。多选同一答卷的每个选项至多计一次；文本原文逐答卷查看；数字均值仅包含该题有效数字回答，跳过/空答不补零；无回答均值为 null/“暂无”。整卷统计与同版本单题结果一致；不同发布版本分开统计，不混用选项含义。验收：TC-S01–TC-S03。

## D09 数据模型与工具链

关联 R01/R13。建议 Python/FastAPI/PyMongo、简单服务端页面、pytest、conda 环境；业务持久化全用 MongoDB。拟拆分账号、问卷、不可变发布版本、答卷，需要持久会话时另建集合。稳定 ID、`schema_version`、`survey_version` 用于本阶段发布快照与答卷追踪。安装版本、Schema、索引、拓扑、依赖可用性在 S1/S2 实测确认；本次不安装。验收：DOC-01、TC-E02。

## D10 第一阶段成果留存

关联 R13。S7 固定第一阶段代码、Schema、数据样例、备份恢复说明及验收证据，保证当前提交可复现。当前不安排第二阶段需求分析、实现、数据迁移或兼容回归。验收：DOC-02、TC-E02。

## S1 采纳记录

日期与时区：2026-10-15，Asia/Shanghai。来源：用户本次完成实验授权、Word 初始需求和 R01–R14；审阅者：Codex 主 agent及内部需求审阅 agent。所有决定对应测试仍待实际执行。

- D01：采纳登录后对创建者匿名，代替游客填写解释，同时满足原文登录与匿名要求；私有判重身份不进入匿名结果。
- D02：采纳默认禁止同账号同问卷多次提交，发布后冻结；允许重复时每次主动填写新 request_id，重试复用 ID。同 ID 不同内容返回冲突。成功请求的相同重试即使问卷后来关闭也返回原回执，不新增答卷。
- D03：采纳保存每次成功提交，页面明确提交前不自动保存。未完成草稿的持久化不在本阶段，解释限制保留，不声称教师确认。
- D04：采纳三类数据驱动规则、显式唯一优先级、首条命中及向前跳转；固定行为便于解释和避免循环，保留后续需求变更可能。
- D05：采纳只校验可达路径、改答案清理旧路径、服务端重算；拒绝路径外答案及旧版本，避免客户端绕过。
- D06：采纳包含上下界、Unicode 码点计数、全空白为空、有限数值/整数判断和配置自检；前后端按同一口径验收。
- D07：采纳不可变发布快照、UTC 时间、截止时刻不受理。S2 使用单节点副本集事务，对问卷 gate 字段实际写入并同时插入答卷；关闭操作也写同一文档，以写冲突确定先后。受理时刻为事务内通过状态/截止条件的 gate 写入时刻；事务重试必须重新取时间并验证。仅 snapshot 读取不能作为保证。
- D08：采纳提交次数与去重人数分开，单选保留每选项人数/次数，多选每份答卷至多计一次，数字均值排除跳过/空答；零有效回答为 null。
- D09：采纳 Python 3.11、FastAPI、PyMongo、Jinja2/原生 JavaScript、pytest/HTTPX 与 conda；MongoDB 使用本项目独立本地副本集。版本从实际 conda 安装锁定。
- D10：采纳本阶段提交快照、Schema、合成数据与真实结果留存，无第二阶段工作。

备选方案（游客匿名、动态修改已发布题目、按 HTTP 到达时刻判关闭、全体问卷单集合）本次不采纳；理由分别为原文认证要求、历史答案语义、并发可验证性和访问/增长边界。上述项目解释不删减原文业务要求；若教师提供新解释，按 workflow 记录差异后调整。
