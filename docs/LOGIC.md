# 第一阶段关键逻辑

本文件记录 S2 契约；后续代码与测试应实现同一语义，不因结果改变预期。依据为已采纳 D01–D10，源码中的实现入口在对应阶段补齐。

## 生命周期与所有权

状态只允许 draft→published→closed。只有草稿可编辑题目、规则和匿名/重复策略；每次编辑以期望 revision 为条件。发布请求携带 revision，事务内读取、校验并条件写入同一版草稿，保存不可变 version=1；编辑竞争后返回冲突或重新读取验证，不能冻结事务外的旧副本。元数据除截止字段外冻结。关闭和截止更新只允许本人，和提交受理写入同一个 survey 文档以处理竞争。所有管理、统计、原文读取均服务端验证 owner_id。

填写必须认证。匿名开关表示对创建者隐藏账号，服务端仍按私有身份判重和去重计人数。UI 在填写前显示匿名范围、重复策略及“提交前不自动保存”。

## 配置检查

题目/选项 ID 稳定且唯一，不含点号或 `$`。选择题至少两个选项；多选 min/max/exact 是非负整数且不超过选项数，exact 与其他边界必须相容。文本边界为非负整数且 min≤max；数字界值有限且 min≤max。不接受未知题型/字段/算子或布尔值伪装数值。

规则来源仅 single/multi/number，目标必须在同卷且严格位于来源之后。同一来源题 priority 不重复，按数值升序首条命中；单选 eq，数字 eq/lt/lte/gt/gte，多选 any/all；条件选项必须真实存在，空条件集合拒绝。无命中进入顺序下一题，末题后结束。不能按“第1题选A跳5”的示例硬编码。

## 答案与路径

从首题开始，以服务端发布配置逐题遍历。已答值先校验，再决定下一题；跳过的必答题不要求作答。optional 空答作为未提供值，不触发长度/数量/范围要求；必答空值报错。单选只允许一个合法 ID；多选为无重复合法 ID 列表；文本保留原文、全空白视为空、按 Unicode 码点计长度；数值严格是有限 int/float 且不是 bool，整数题接受数学整数（包括1.0），不能静默截断。

部分预检区分键是否存在：缺键表示尚未作答并停在该题；显式 null（或该类型的合法空值）表示已主动跳过可选题，可继续前进；必答空值仍拒绝。预检返回的 answers 保留已访问题的 null，path 包括下一待答题，以便页面继续预检。完整提交允许可选题为空但必须满足所有可达必答题，最终拒绝路径外或未知答案；持久化时省略空答值，path 仍保留实际访问题。前端回改早期答案时移除其后答案，再按新路径重新前进。所有最终答案经同一校验器，不信任客户端上报路径、配置或身份。

S4 的必答配置还检查是否至少存在一个非空合法答案，细则见 D06 补充。实现入口为 questions.check_definition / validate_answer / evaluate_path；POST /next 只读发布配置，不保存未完成回答。

## 提交与统计

request_id 与规范化 `{version,answers}` 摘要稳定，防重复索引和受理事务协议见 DATABASE。已成功请求先重放；新请求必须在成功事务中通过发布/截止 gate，写入完整 response。事务重试不改请求 ID，不在回调发送任何外部消息。

统计只使用成功 response，按发布版本分开。单选同时给选项次数及去重人数；多选每份答卷每个选项最多一次；文本/数字原值可查看，数字平均跳过空答和路径跳过题，无有效值返回 null。匿名响应通过白名单去除私有身份，不以“界面没显示”替代后端验证。

测试分层：S3 验证认证/配置/发布/所有权；S4 验证校验器与路径；S5 验证提交事务、并发、匿名与统计；S6 做浏览器完整流程及干净环境复现。具体用例及实际结果分别在 TEST_PLAN、TEST_REPORT 和 results 下记录。
