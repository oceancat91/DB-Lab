## 原文硬要求

### R01 技术约束与 MongoDB 设计

来源：“三、技术要求”“四、MongoDB 设计要求”。所有持久业务数据在 MongoDB 中，不使用关系数据库或现成问卷系统框架；语言、后端和前端不限。须解释数据库设计、为何不采用关系数据库结构、为何适合 MongoDB。说明应依据课程约束和访问模式，不能泛称关系数据库不能做问卷。

实施：S1、S2；验收：DOC-01、TC-E02。

### R02 账号及拥有者隔离

来源：“初始用户需求／一、用户账号功能”。注册、登录，用户具有用户名、密码和注册时间；用本人账号创建问卷，只看到自己创建的问卷并查看统计。服务端所有权和密码哈希是实现该要求的项目规范。

实施：S3；验收：TC-A01、TC-A02、TC-A03。

### R03 问卷创建与生命周期

来源：“初始用户需求／二、问卷创建与管理”。标题、说明、匿名开关；本人列表、发布、设置截止时间、关闭和可访问分享链接（原文示例 `/survey/xxxxxx`）。填写者需先登录。

实施：S3、S5；验收：TC-Q01、TC-Q02、TC-Q03、TC-R05。

### R04 单选题

来源：“初始用户需求／三／1. 单选题”。配置选项、是否必答，必答时必须选择。

实施：S3、S4；验收：TC-Q02、TC-V01。

### R05 多选题

来源：“初始用户需求／三／2. 多选题”。支持最少、最多和精确选择数量，填写时校验。

实施：S3、S4；验收：TC-Q02、TC-V02、TC-V05。

### R06 文本填空

来源：“初始用户需求／三／3. 填空题”。支持文本填写和最少、最多字数限制。

实施：S3、S4；验收：TC-Q02、TC-V03。

### R07 数字填空

来源同 R06。支持数值最小/最大值和整数要求，填写时检查合法性。年龄 0–120、手机号为整数是原文示例，不代表所有数字题必须使用同一约束。

实施：S3、S4；验收：TC-Q02、TC-V04、TC-V05。

### R08 可配置跳转

来源：“初始用户需求／四、题目跳转功能”。单选、多选和数字填空的答案可驱动跳转；填写时自动进入对应题目。规则由问卷配置，不能把题号和分支写死在程序里。

实施：S2、S4；验收：TC-J01、TC-J02、TC-J03、TC-J04、TC-J05。

### R09 填写与提交保存

来源：“初始用户需求／五、填写问卷”。通过链接进入，按顺序或按规则跳转；输入不合法时提示错误；完成后提交，每次填写被保存。未完成草稿是否自动保存原文未定义，须按 D03 记录解释。

实施：S4、S5、S6；验收：TC-R01、TC-R02、TC-E01。

### R10 匿名、多人及重复填写

来源：“初始用户需求／二、五”。支持匿名、多人同时填写、允许时同一人多次填写。登录与匿名的关系、重复开关及幂等须单独决策。

实施：S1、S5；验收：TC-R03、TC-R04、TC-R05。

### R11 自动统计

来源：“初始用户需求／六、查看统计结果”。创建者查看整卷和单题统计；单选每选项人数及总回答人数，多选每选项次数，填空全部内容，数字平均值；从已填写数据自动生成。重复填写下“人数”口径按 D08 明确展示。

实施：S5；验收：TC-S01、TC-S02、TC-S03。

### R12 必要测试及结果记录

来源：“六、测试要求”“七／3. 测试用例”。至少覆盖创建问卷、添加题目、跳转、校验、提交、统计；自动化、手工或 API 均可。用例有清楚步骤、输入、输出和结果。

实施：S3–S6；验收：DOC-02、TC-E01、TC-E02，并审阅全部第一阶段用例。

### R13 第一阶段完整交付

来源：“七、提交内容”。当前第一阶段须交：可运行代码（含后端、MongoDB schema、配置说明）；系统说明、数据库设计、API、关键逻辑文档；测试用例与结果；完整项目完成报告。报告覆盖目标、系统/MongoDB/跳转/校验设计、AI 过程、测试结果、问题与解决方法。

实施：S6、S7；验收：DOC-02、TC-E02。
