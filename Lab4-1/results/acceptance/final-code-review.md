## 链路与数据规则核对

1. 身份与所有权：管理、统计和明细路由都先取得会话用户，拥有者由服务端查询条件验证；公开分享读取仍须登录。密码使用带独立盐的 scrypt；会话摘要与过期时间在 MongoDB 中，不仅依赖 TTL 清理。
2. 草稿与发布：草稿保存和发布检查 revision；发布事务保存不可变版本。题目和规则由配置驱动，服务端检查题型、边界、合法选项、目标及优先级，没有把示例题号写成业务分支。
3. 填写与路径：前端每次前进/返回调用 `/next`，采用服务端返回的路径；回改清除后续答案，选答空值使用 null。服务端重新计算最终路径并拒绝未知题、路径外题及非法答案。
4. 提交与并发：前端冻结同一次提交的答案快照和请求编号，遇到不确定网络/服务端结果锁定改答并重试；明确成功后显示回执。服务端先检查已有回执，再通过真实事务 gate 写入与答卷插入，关闭/截止操作竞争同一问卷文档；条件唯一索引区分禁止重复和允许重复。
5. 统计与匿名：统计先校验拥有者，再从固定版本的 MongoDB 快照读取答卷；提交次数、去重人数、选项次数/人数和数字均值分别计算。文本/数字原文可查看；空答/跳过不补零。匿名明细使用服务端白名单，前端也不为匿名答卷补出账号或私有判重标识。
6. 会话切换：正常退出时对未保存修改和未提交回答提示确认，然后清空填写状态与提交快照；新登录成功后清空旧填写及结果状态。提交前另核对当前账户，防止明显的跨窗口换号后直接发送旧回答。
7. 持久化：源码中的账号、会话、问卷、版本及成功答卷均使用 MongoDB；浏览器中的未提交答案是已明确说明的临时页面状态，没有以文件、内存业务库或关系数据库替代成功答卷持久化。

## 统计操作后的滚动与焦点

定位：`survey_app/static/app.js:96` 的 `action`、`:801` 的 `loadResults`、`:947` 起的统计/明细事件。

- 源码没有为统计按钮调用 `scrollTo`、修改 location 或主动聚焦页面顶部。
- `action` 暂时禁用触发控件并设置 `main.inert`，完成后解除；它只为指定的填写标题恢复焦点，没有通用的原控件焦点恢复逻辑。
- `loadResults` 会先用一行“正在读取结果”替换旧结果。较长结果被暂时压缩时，文档高度下降可能使浏览器调整滚动位置；控件失焦也可能影响后续键盘导航。

这是基于源码的易用性风险解释，本轮未在浏览器重现或测量具体滚动距离。它不改变 API 请求、问卷归属或统计值，结合既有实际浏览器主链路记录，不作为本阶段功能阻塞。可选的小修方向是请求时保留结果容器高度，并在解除 inert 后对仍存在的原控件调用 `focus({preventScroll:true})`，或只锁定正在修改的表单区域；不能简单删去保护而重新引入保存期间内容被响应覆盖的问题。本轮未实施这些改动。
