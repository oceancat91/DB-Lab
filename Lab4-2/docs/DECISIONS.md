## D11 题目是实体，内容是版本

关联 R15/R19。原文只要求“保存题目并复用”，没有说明题目内容与问卷里那份副本的关系。

备选：①问卷直接引用题目实体，读问卷时实时取最新内容；②问卷保存题目副本，另记题目 ID；③复制一份题目文档给每个问卷。

采纳：②。`questions` 只存身份与元数据（所有者、题型、标题、当前版本号、状态、来源），内容存进 `question_versions` 的不可变版本；导入问卷时把版本内容复制进 `surveys.draft.questions`，并写入 `question_version` 标记。问卷读取路径（发布、填写、统计）完全不依赖题目库，因此题目库不可用时老问卷仍可读。

理由：问卷的读取模式是“整卷一次读、按快照冻结”，如果实时引用题目库，任何一次题目改版都会改写已发布问卷的语义（与 R17 冲突）。复制内容 + 版本号标记同时满足“复用”和“旧卷不变”。

影响：同一题目的内容在问卷快照里有多份副本，占用空间且可能出现“同一版本号、内容却不同”的异常状态（若被绕过校验写入）。因此 `normalize_question_refs` 会核对副本内容与版本是否一致，见 D18。验收：TC-L01、TC-L03、TC-L05；DOC-Q01、DOC-Q03。

## D12 版本不可变、历史只追加

关联 R18/R19。原文要求“看到历史版本”“知道新题从哪个题改来”“可以恢复旧版本”，但没有定义“恢复”是回滚还是新增。

备选：①原地改版本并保留少量旧值；②版本只追加，恢复=按旧内容新增一版；③允许把 `current_version` 指回旧号（回滚）。

采纳：②。`question_versions` 的 `(question_id, version)` 唯一，已写入的版本不被更新或删除；“恢复旧版本”插入一个新版本，其 `restored_from` 记来源版本号、`supersedes` 记被替代的当前版本号、`derived_from` 记“改自哪个题目哪个版本”，`current_version` 继续 `+1`。理由：回滚（③）会让“当前版本号”指向一条旧记录，历史出现分叉且无法解释“第 3 版为何等于第 1 版”；追加式历史让每一步都可解释、可审计，也让“旧问卷钉住的版本号”永远指向同一内容。

影响：版本号只增不减，历史长度随修改次数线性增长；没有删除/归档接口，这一点在需求文档中列为未实现。验收：TC-L03；DOC-Q03。

## D13 共享是使用授权，不是复制，也不转移所有权

关联 R16。原文“可以把题目共享给其他用户”“共享后仍然可以继续使用同一个题目”没有说明共享后对方拿到的是副本还是同一题目。

备选：①共享即复制一份给对方（对方拥有独立副本）；②共享为授权，对方在自己问卷里引用同一题目 ID 与版本；③共享为共同所有权（双方都能改）。

采纳：②。`question_shares` 记录 `(question_id, grantee_id)`；所有者仍是唯一所有者，共享不产生副本、不改变 `owner_id`，取消共享后对方立即失去访问。对方要“独立改”时使用 fork（D14），另存为新题目。

理由：原文的“共享后仍可继续使用同一个题目”与“老师做的题目学生直接用”指向同一题目的复用；若共享即复制，则“同一个题目”不再成立。共同所有权（③）会让“已发布问卷不受他人改题影响”的边界变得依赖他人行为。

影响：共享是单向的（A 共享给 B，不等于 B 能反向共享）；被共享者看到的是所有者当前可用的版本集合，导入时自行选版本，不自动跟随新版；所有者的改版不会通知被共享者（无通知机制）。验收：TC-L04；DOC-Q02、DOC-Q03。

## D14 谁能改：所有权、版本、共享与 fork 的权限矩阵

关联 R16/R17/R19/R20。原文只说“其他用户可以在自己的问卷里使用”，没有说明被共享者能否改题。

备选：①被共享者可以给同一题目追加版本；②只有所有者能追加版本与共享，被共享者只能使用或 fork；③被共享者完全只读（不能 fork）。

采纳：②。所有者可以新建版本、恢复、共享、取消共享、删除题库条目；被共享者可以查看、导入自己的问卷、fork 出新题目，但调用“新建版本/恢复/共享/取消共享”得到 404（不泄露题目存在性之外的权限信息）。③被否决，因为原文第四、五条要求“基于一个题创建新版本/单独修改”，若被共享者连 fork 都不允许，团队协作场景无法完成。

实现细节：`new_version`/`restore_version`/`share`/`unshare` 都走 `_accessible(..., owner_only=True)`，非所有者（含被共享者）统一 404；`fork` 只要求可访问。问卷内的修订接口在“题目可访问但不是所有者”且模式为 `new_version` 时返回 403，因为此时题目存在性已通过问卷上下文暴露，用 403 表达“存在但无权”更准确。

影响：权限差异导致同一资源在不同入口返回 404 或 403（见 [API.md](API.md) 的错误语义一节），客户端不能把 403/404 当作同一含义。验收：TC-L02、TC-L04、TC-L07；DOC-Q02。

## D15 已发布问卷冻结，但题目实体可继续演进

关联 R17/R19。原文要求“已发布问卷里的题目不能被修改”“不同问卷可以使用不同版本”。

采纳：问卷一旦发布（或关闭），其题目内容、顺序、跳转、匿名与重复策略都不可再改，任何写接口返回 409 `immutable`；与此同时，题目实体可以继续产生新版本，其他问卷可以钉新版本。二者不矛盾：冻结的是问卷快照，不是题目库。

理由：冻结保证历史答卷与当时的题目定义一一对应；题目库的演进满足“同一题在不同问卷里用不同版本”。

影响：不存在“把已发布问卷升级到新版本题目”的接口，也没有“问卷第二版”；`published_version` 恒为 1（复用一阶段实现）。若将来需要改已发布问卷，只能新建问卷。验收：TC-L05；DOC-Q03。

## D16 题库条目钉住版本，更新必须显式

关联 R21。原文“题库里的题可以更新版本”没有说明是自动跟随还是手动更新。

备选：①题库条目只存题目 ID，永远取当前版本；②条目钉住一个具体版本，另提供显式更新；③双模式（跟随/钉住）由用户选择。

采纳：②。`question_bank_items.question_version` 记录钉住的版本；`bank_detail` 用 `outdated` 标记“钉住版本 ≠ 当前版本”；`PATCH /api/banks/{bank_id}/items/{question_id}` 在省略版本时更新到当前版本，也可指定版本（含回退到旧版）。理由：题库是“选材清单”，若自动跟随最新版，一次改版会悄悄改变所有后续从题库建卷的题目内容，无法解释“我上次选的是哪一版”；③会增加状态与界面复杂度，原文未要求。

影响：题库会长期保留旧版本引用，旧版本不会被清理（也没有清理接口）；界面只在 `outdated` 时显示“更新版本”按钮。验收：TC-L08；DOC-Q01、DOC-Q02。

## D17 跨问卷统计的可见范围与口径

关联 R22/R20。原文要求“看某一道题在所有问卷中的回答情况”，但没有定义“所有”是否包含别人的问卷。

备选：①任何可访问该题目的人都聚合全部问卷；②所有者聚合全部，被共享者只聚合自己的问卷；③只有所有者能看统计。

采纳：②。响应里的 `scope` 字段明示范围：所有者 `all surveys`，被共享者 `own surveys only`；被共享者的聚合只包含 `owner_id` 等于自己的问卷快照。理由：题目内容可以共享，但答卷数据属于各问卷所有者，把他人答卷的分布透露给被共享者超出了“共享题目”的授权范围；③又会让“团队复用同一题”的人无法核对自己的数据。

口径：只统计已发布快照中的回答（草稿不能填写）；按题目版本分桶；选择题给每选项次数与标签、文本给原值（上限 200 条）、数字给均值（排除空答），沿用一阶段 D08。不落统计副本，每次请求现算。

已知不一致：使用情况接口（R20）没有做同样的范围过滤，被共享者能看到所有者的问卷标题与状态。这是实现与本文范围定义之间的偏差，未修复、未验证影响，记录在 [REPORT_STAGE2.md](REPORT_STAGE2.md) 第 9 节。

验收：TC-L09；DOC-Q02、DOC-Q03。

## D18 数据信任边界：客户端标记要复核，迁移只追加

关联 R15/R17/R18。这一条把两个“不能相信已有数据/客户端声明”的边界放在一起，因为二者都决定“库里的题目副本是否可信”。

客户端 `question_version`：问卷保存接口接受客户端提交的题目数组，其中可能带有 `question_version`。若直接采信，客户端可以声称“这是题目 X 的 v7”却提交任意内容，统计与使用情况就会把伪造内容算进题目 X。采纳：服务端在保存时复核——题目必须存在、当前用户可访问、该版本存在、副本的五个内容字段（type/title/required/options/validation）与版本记录逐字段相等；任一不满足就**删除**标记，把该题降级为问卷本地题目，而不是报错。理由：报错会让“先导入再本地微调”的正常流程无法保存；删除标记既保证统计不被污染，又保留用户编辑能力。

一阶段数据迁移：迁移脚本只读取 `surveys.draft.questions` 与 `survey_versions.questions`，为没有实体记录的题目 ID 补建 `questions` + `question_versions`（`origin=migrated`），**不更新、不删除、不重写**任何问卷或快照文档；内容冲突只记录在报告的 `conflicts` 里，不擅自选一个版本覆盖。理由：一阶段快照是历史答卷的解释依据，改写它等于篡改历史；迁移必须可重复执行（已存在则跳过）。

影响：迁移无法修复“同一题目 ID 在不同问卷里内容不同”的历史数据，只能报告；被降级的本地题目不再参与跨问卷统计（这是有意的）。验收：TC-L06、TC-L09；DOC-Q03。

- D11：采纳“实体 + 版本 + 问卷副本”，否决实时引用与逐卷复制题目文档。
- D12：采纳追加式历史与“恢复=新增版本”，否决回滚 `current_version`。
- D13：采纳共享为授权，否决共享即复制与共同所有权。
- D14：采纳“只有所有者能建版本/共享，被共享者可 fork”，权限失败按入口分别返回 404/403。
- D15：采纳发布即冻结、题目实体继续演进、`published_version` 恒为 1。
- D16：采纳题库条目钉住版本 + 显式更新，否决自动跟随与双模式。
- D17：采纳统计范围按所有者/被共享者区分，并承认与使用情况接口的不一致。
